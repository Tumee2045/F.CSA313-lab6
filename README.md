# Хэсэг A: Category-Partition — `POST /transfer`

## Олон алдааны давуу эрэмбэ

Нэг хүсэлтэд хэд хэдэн алдаа зэрэг байвал дараах эрэмбээр **эхнийх нь** буцна:

```
ERROR_NO_FROM → ERROR_FROZEN → ERROR_NO_TO → ERROR_SAME_ACCOUNT
              → ERROR_BAD_AMOUNT → ERROR_INSUFFICIENT → ERROR_LIMIT
```

**Үндэслэл:** эхлээд "хэн" (from → to), дараа нь "хэдийг" (amount) шалгана — илгээгч
данс байхгүй/царцаагдсан бол үлдэгдэл, лимитийг шалгах нь утгагүй төдийгүй, царцаагдсан
дансны үлдэгдэл хүрэлцэх эсэхийг (`ERROR_INSUFFICIENT`) задруулах нь мэдээллийн аюулгүй
байдлын эрсдэл; amount дотроо хамгийн хямд шалгалт (≤ 0) түрүүлж, үлдэгдэл (хатуу
хязгаар) нь өдрийн лимитээс (бодлогын хязгаар) өмнө шалгагдана.

## A1 — Сонголт ба төлөөлөх утгууд

4 параметрээс 4 сонголт, дээр нь тодорхойлолтод шууд бичигдээгүй ч үр дүнд нөлөөлдөг
**далд орчны сонголт** 1 (өдрийн лимит хэр дүүрсэн байсан) — нийт 5 сонголт.

| Сонголт | Төлөөлөх утга | Тайлбар | Тэмдэглэгээ |
|---|---|---|---|
| **From** (илгээгч данс) | `Valid` | байгаа, царцаагдаагүй | |
|  | `Frozen` | байгаа, царцаагдсан | `[ERROR]` |
|  | `Missing` | бүртгэлгүй ID | `[ERROR]` |
| **To** (хүлээн авагч данс) | `Valid` | байгаа, from-оос өөр | |
|  | `Missing` | бүртгэлгүй ID | `[ERROR]` |
|  | `SameAsFrom` | from-той ижил ID | `[ERROR]` |
| **Amount** (дүн) | `Normal` | 0 < дүн < үлдэгдэл, лимитэд багтана | |
|  | `EqualsBalance` | дүн = үлдэгдэл (яг хязгаар) | `[SINGLE]` |
|  | `Zero` | дүн = 0 (≤ 0 ангийн хязгаар) | `[ERROR]` |
|  | `OverBalance` | дүн > үлдэгдэл | `[ERROR]` |
|  | `OverBalanceAfterFX` | тоон утгаараа үлдэгдлээс бага, хөрвүүлсний дараа их | `[ERROR]` `[IF FX]` |
|  | `OverLimit` | үлдэгдэлд багтана, өдрийн лимитээс хэтэрнэ | `[ERROR]` |
| **Currency** (валют) | `Same` | дансны валюттай ижил | |
|  | `Different` | өөр валют — хөрвүүлэлт хийгдэнэ | `[property FX]` |
| **DailyUsed** (далд орчин: өдрийн лимитийн ашиглалт) | `None` | өнөөдөр шилжүүлэг хийгээгүй | |
|  | `Partial` | лимитийн хэсэг ашиглагдсан | |
|  | `Exhausted` | лимит бүрэн дууссан | `[ERROR]` |

## A2 — Хязгаарлалтууд ба үндэслэл

| Утга | Тэмдэглэгээ | Үндэслэл |
|---|---|---|
| `From=Frozen`, `From=Missing` | `[ERROR]` | Бусад сонголтоос үл хамааран алдаа буцаах тул бусад утгатай хослуулах нь шинэ мэдээлэл өгөхгүй — нэг удаа шалгахад хангалттай. |
| `To=Missing`, `To=SameAsFrom` | `[ERROR]` | Мөн адил: хүлээн авагчийн алдаа нь дүн, валютаас хамаарахгүй. |
| `Amount=Zero` | `[ERROR]` | `amount ≤ 0` ангийн хязгаарын утга; үлдэгдэл, лимитээс хамаарахгүйгээр `ERROR_BAD_AMOUNT`. |
| `Amount=OverBalance`, `OverLimit` | `[ERROR]` | Тус бүр нэг тодорхой алдааны анги (`ERROR_INSUFFICIENT`, `ERROR_LIMIT`). |
| `Amount=OverBalanceAfterFX` | `[ERROR]` `[IF FX]` | "Хөрвүүлсний дараа л хэтрэх" нь зөвхөн `Currency=Different` (property `FX`) үед боломжтой; ижил валютад ийм тохиолдол оршихгүй. |
| `Amount=EqualsBalance` | `[SINGLE]` | Алдаа биш (дүн үлдэгдлээс "хэтрэхгүй") хязгаарын утга — `>` ба `≥`-ийн алдааг барина, гэхдээ бусад бүх утгатай хослуулах шаардлагагүй. |
| `Currency=Different` | `[property FX]` | Хөрвүүлэлт хийгдэхийг тэмдэглэж, `[IF FX]` утгыг идэвхжүүлнэ. |
| `DailyUsed=Exhausted` | `[ERROR]` | Лимит дууссан бол ямар ч эерэг дүн `ERROR_LIMIT` болно. |
| `From=Missing` → `Amount ∈ {Normal, Zero}`, `DailyUsed=None` | `[IF FromExists]` | Байхгүй дансанд үлдэгдэл ч, өдрийн лимит ч байхгүй тул "үлдэгдэлтэй тэнцүү/хэтэрсэн", "лимит дүүрсэн" гэсэн утгууд **тодорхойгүй** (боломжгүй хослол). |

### "N → M" тооцоо

| Алхам | Тооцоо | Тест фрэймийн тоо |
|---|---|---:|
| Бүрэн олонлог | 3 × 3 × 6 × 2 × 3 | **324** |
| `[IF]` хязгаарлалтын дараа (боломжгүй хослол хасагдсан) | 324 − 114 | **210** |
| `[ERROR]` — 9 утга, тус бүр 1 фрэйм | (1 × 1 × 2 × 2 × 2) + 9 | **17** |
| `[SINGLE]` — 1 утга, 1 фрэйм | (1 × 1 × 1 × 2 × 2) + 9 + 1 | **14** |

**324 → 210 → 14.** Хэвийн утгуудын үржвэр: From 1 × To 1 × Amount 1 × Currency 2 ×
DailyUsed 2 = 4; дээр нь `[ERROR]` 9 ба `[SINGLE]` 1.

# Хэсэг B: PICT

## B1 — Браузерын жишээ

```bash
pict browser.model | tee results/browser-2way.txt
pict browser.model /o:3 > results/browser-3way.txt
```

| | Мөрийн тоо | Харьцуулалт |
|---|---:|---|
| Бүрэн олонлог | 144 | 3 × 3 × 2 × 2 × 2 × 2 |
| **2-way** (`browser-2way.txt`) | **10** | лекцэд гараар 9 |
| **3-way** (`browser-3way.txt`) | **20** | 144-ийн ~14% |

**Яагаад 9 биш 10 вэ (greedy):** Онолын доод хязгаар нь 3 × 3 = 9 (Content × Cookies-ийн
9 хос тус бүр өөр мөрөнд байх ёстой), лекцэд гараар яг 9-д багтаасан. PICT нь **greedy**
алгоритмтай — мөр бүрийг "одоогоор хамрагдаагүй хосыг аль болох олноор хамрах" байдлаар
нэг нэгээр нь сонгодог бөгөөд өмнө сонгосон мөрөө эргэж засдаггүй тул глобал оновчтой
шийдийг ЗААВАЛ олдоггүй, энд 1 мөр илүү гаргасан. Үүний хариуд PICT хурдан бөгөөд
ажиллуулах бүрт ижил үр дүн өгдөг; 10 мөр ч бүх хосыг хамарсан хүчинтэй covering array.

**3-way:** 20 мөр — бүрэн олонлог 144-өөс 7 дахин цөөн атлаа аливаа 3 параметрийн бүх
хослолыг хамарна (доод хязгаар 3 × 3 × 2 = 18).

**Гаралтыг уншихад:**

- **Хязгаарлалтгүй (19 мөр):** happy path мөр **нэг ч гараагүй** — хамгийн чухал тест
  алга. 19 мөрийн 16 нь 2 ба түүнээс олон алдаатай (2 алдаа — 7, 3 алдаа — 8, 4 алдаа — 1).
  Мөн 6 мөр утгагүй: жишээ нь `From=Missing` + `Amount=EqualsBalance` (байхгүй дансны
  үлдэгдэлтэй тэнцүү дүн гэж байхгүй).
- **Хязгаарлалттай (20 мөр):** боломжгүй мөр 0 болж, happy path 1 гарсан, гэвч 17 мөр
  олон алдаатай хэвээр. Олон алдаатай мөр **юуг шалгаж байгаа нь тодорхойгүй**: жишээ нь
  `Frozen, Missing, OverLimit, Same, Exhausted` мөрөнд 4 алдаа байгаа ч давуу эрэмбээр
  зөвхөн `ERROR_FROZEN` буцах тул `ERROR_NO_TO`, `ERROR_LIMIT`-ийн код огт ажиллахгүй
  (error masking) — хос нь "хамрагдсан" гэж тоологдсон ч бодитоор шалгагдаагүй.
- **Хязгаарлалт нэмэхэд мөр 19 → 20 болж ӨССӨН:** хязгаарлалт нь хослолыг хориглосноор
  нэг мөрөнд олон шинэ хосыг "багцлах" боломжийг багасгадаг тул хосыг хамрахад илүү
  мөр хэрэгтэй болдог.
- **`~` хэрэглэхэд (24 мөр):** мөр бүрд хамгийн ихдээ **1** алдаа — 19 мөр яг нэг
  алдаатай, 5 мөр happy path. Мөр бүр яг нэг алдааны ангийг шалгах тул oracle нь
  хоёрдмол утгагүй. Үнэ нь: сөрөг утгууд хоорондоо хосолж чадахгүй тул мөр 20 → 24 болсон.

**`~` хэрэглэхэд A2-ын хязгаарлалт хэрэгтэй хэвээр үү? — Тийм.** `~` нь зөвхөн "нэг
мөрөнд нэг сөрөг утга" гэдгийг баталгаажуулдаг, харин утгын **семантик боломжгүй
байдлыг** мэддэггүй. Шалгахын тулд `~`-тэй, хязгаарлалтгүй `transfer-neg-nc.model`-ийг
ажиллуулахад 25 мөрөөс **2** нь боломжгүй гарсан: `OverBalanceAfterFX` + `Currency=Same`,
мөн `From=Missing` + `Amount=EqualsBalance` + `DailyUsed=Partial`. Иймд `[ERROR]` →
`~`, `[IF]` → `IF ... THEN` гэж **хоёуланг нь** буулгах шаардлагатай. Харин PICT-д
`[SINGLE]`-ийн дүйцэл байхгүй — `EqualsBalance` нь `transfer-neg.txt`-ийн 7 мөрөнд
давтагдсан.

### PICT-ийн гаралтаас 4 бодит тест кейс

## B3 — Гараар хийсэн A3 ба PICT-ийн харьцуулалт

| | Гараар (category-partition, A3) | PICT (pairwise) |
|---|---|---|
| Алдааны семантик | **Сайн барина** — `[ERROR]`, `[SINGLE]`, давуу эрэмбэ, oracle мөр бүрд бий | Мэдэхгүй — `~` ба `IF`-ээр зааж өгөхгүй бол утгагүй, олон алдаатай мөр гаргана |
| Хосын хамралт | Баталгаагүй — хэвийн утгын хослолыг хүн сонгоно, орхигдож болно | **Баталгаатай** — утгын хос бүр дор хаяж нэг мөрөнд |
| Хүлээгдэх үр дүн (oracle) | Хүснэгтэд шууд бичигдсэн | Байхгүй — мөр бүрд хүн нэмж бичнэ |
| Хязгаарын утга | `[SINGLE]`-ээр нэг удаа | `[SINGLE]` байхгүй, давтагдана |
| Зардал / өргөжих чадвар | Сонголт нэмэгдэхэд гараар дахин хийнэ | Модель засаад дахин ажиллуулна, 3-way руу нэг сонголтоор шилжинэ |

## Дүгнэлт

Хоёр арга өөр асуултад хариулдаг: category-partition нь "**ямар** утгыг, **яагаад**
шалгах вэ" гэдгийг хүний бодлоор тогтоодог бол PICT нь "тэдгээрийг **хэрхэн** цөөн
мөрөнд багцлах вэ" гэдгийг автоматаар шийддэг. Гараар хийсэн A3 хүснэгт алдааны
семантикийг илүү сайн барьсан — мөр бүр яг нэг зорилготой, oracle нь тодорхой, 324
хослолыг 14 фрэйм болгосон; харин хэвийн утгуудын хосын хамралтыг баталгаажуулдаггүй.
PICT-ийн хязгаарлалтгүй гаралт (19 мөр) нь хосыг бүрэн хамарсан ч happy path нэг ч
мөргүй, 6 боломжгүй мөртэй, нэг мөрөнд 4 хүртэл алдаатай байсан нь "хосыг хамарсан"
гэдэг "утгатай тест" гэсэн үг биш болохыг харуулсан. `~` тэмдэглэгээ error masking-ийг
шийдэж мөр бүрийг нэг алдаатай болгосон (24 мөр, 5 happy path), гэхдээ туршилтаар
шалгахад семантик боломжгүй 2 мөрийг арилгаж чадаагүй тул A2-ын `IF` хязгаарлалт
хэрэгтэй хэвээр үлдсэн. Хамгийн их бодол шаардсан алхам нь **A2 — хязгаарлалт тавих**
байлаа: `[ERROR]` (алдаа буцаана), `[SINGLE]` (алдаа биш хязгаар), `[IF]` (хослол
боломжгүй) гурвыг ялгах, ялангуяа "байхгүй дансны үлдэгдэл" гэдэг утга огт оршихгүйг
олж харах хэрэгтэй байв. Давуу эрэмбийг код байхгүй үед өөрөө тогтоох нь мөн бодол
шаардсан — үүнгүйгээр олон алдаатай мөрийн oracle бичих боломжгүй. Далд орчны сонголт
(өдрийн лимитийн ашиглалт) болон `OverBalanceAfterFX` утга нь параметрийн жагсаалтаас
шууд харагдахгүй, зөвхөн дүрмийг анхааралтай уншихад л гарч ирсэн. Greedy алгоритмын
улмаас PICT браузерын жишээнд гарын 9-ийн оронд 10 мөр өгсөн нь хэрэгсэл хамгийн
оновчтойг биш, "хангалттай сайн"-ыг хурдан өгдгийг харуулав. Эцэст нь хамгийн зөв
хэрэглээ бол хоёуланг нь хослуулах: category-partition-оор сонголт, хязгаарлалтаа
гаргаж, түүнийгээ PICT модель руу (`~`, `IF`) буулгаад, гаралтын мөр бүрд oracle-оо
гараар бичих юм.
